# アーキテクチャ

## 画面構成

### デスクトップ (961px 以上)

五線譜と設定エリアが横並び (`flex-direction: row`)。

```
┌──────────────────────────────────────┐
│         開始オーバーレイ              │  ← クリック/キー入力で消える
├────────────────────┬─────────────────┤
│                    │  設定エリア       │
│   五線譜エリア      │  - 音部記号      │
│   (VexFlow SVG)    │  - 調号・臨時記号 │
│                    │  - 音域          │
│                    │  - 音色・音量    │
│                    │  - 鍵盤表示モード │
│                    │  - ヒント (折畳) │
├────────────────────┴─────────────────┤
│  MIDI ステータス                      │
├──────────────────────────────────────┤
│              鍵盤エリア               │
│  (HTML/CSS で動的生成)                │
└──────────────────────────────────────┘
```

### モバイル (960px 以下)

五線譜が全幅になり、設定は右上のトグルボタンから右スライドインパネルで表示。CSS チェックボックスハックにより JS 不要で開閉する。背景オーバーレイのタップで閉じる。

```

├──────────────────────┐☰│─┤  ← ☰ 設定トグル (z-index: 50)
│                      │  │
│   五線譜エリア        │  │
│   (全幅)             │  │
│                      │  │
├──────────────────────┘  │
│  MIDI ステータス         │
├──────────────────────────┤
│         鍵盤エリア        │
└──────────────────────────┘

☰ タップ時:
         ┌────────────┐
  ░░░░░░░│ 設定エリア   │  ← 右から 260px スライドイン (z-index: 40)
  ░░░░░░░│             │
  ░░░░░░░│             │     ░ = 背景オーバーレイ (z-index: 30)
  ░░░░░░░│             │         タップで閉じる
  ░░░░░░░│             │
```

横向き (`max-height: 500px`) ではさらに五線譜・鍵盤・余白を圧縮して画面内に収める。

### 開始オーバーレイ

ブラウザは AudioContext をユーザージェスチャーなしに起動できない。MIDI 入力はジェスチャーとして認識されないため、最初にクリックまたはキー入力で `Tone.start()` を呼び出して AudioContext を resume する。

### 五線譜エリア

VexFlow の `Renderer` (SVG バックエンド) で描画。`Renderer` と SVG 要素はキャッシュし、サイズ変更がなければ再利用する。再描画時は SVG の内容のみクリアする。

- 問題の音符は黒い全音符で表示
- 「押した音を譜面に表示」ヒント有効時は、入力音を青い全音符で重ねて描画 (2 Voice 構成)
- 正誤フィードバックはエリアの枠色で表現 (緑: 正解、赤: 不正解)

### 設定エリア

HTML の `<input>` / `<select>` で構成。変更時にイベントリスナーで状態変数を更新し、必要に応じて `nextQuestion()` や `buildKeyboard()` を再実行する。

### 鍵盤エリア

`buildKeyboard()` が設定音域に基づいて DOM を動的生成する。

- 白鍵: `div.white-key` を flexbox で横並び
- 黒鍵: `div.black-key` を `position: absolute` で白鍵に重ねる
- 各キーに `data-note` / `data-octave` 属性を持たせ、ヒント表示や入力判定に利用

## 出題ロジック

1. 現在の設定 (音域、調号、臨時記号) から有効な MIDI 番号のプールを構築
2. プールからランダムに 1 つ選択
3. MIDI 番号を調号に基づく表記に変換 (`midiToNoteInfoForKey`)
   - スケール音 → そのまま (臨時記号の表示なし)
   - 非スケール音 → 調号との関係でナチュラル、シャープ、ダブルシャープ等を決定
4. 加線が多くなる音域には 8va / 8vb アノテーションを付与し、表示オクターブをシフト

## 判定ロジック

入力音と出題音の**半音番号** (0-11) を比較する。異名同音 (A# と Bb など) は同一として扱う。

| 入力方法 | オクターブ判定 | 理由 |
|---------|--------------|------|
| MIDI キーボード | あり | 鍵盤がオクターブを特定できる |
| マウス/タッチ | あり | クリックした鍵に `data-octave` がある |
| PC キーボード | なし | 12 キーしかなく、オクターブを指定できない |

## Synth の生成タイミング

`PolySynth` はモジュールのトップレベルで生成する。Tone.js は import 時に AudioContext を作成するため、Synth 生成を遅延させるとコンテキスト不整合が起きる。`Tone.start()` はオーバーレイクリック時に呼び出して AudioContext を resume する。

## 正解後の状態遷移

1. 正解判定 → `currentNote = null` (追加入力をブロック)
2. 枠を緑に変更 (800ms)
3. `nextQuestion()` で次の問題を生成、`currentNote` を再設定
